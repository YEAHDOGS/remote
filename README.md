# DOGS Remote

A native Kotlin Android app that turns a phone with an IR blaster (built for the
OnePlus 12R) into a universal TV remote.

## What it does

- **Magic Mode** — one tap rapidly tries TV volume-up codes across variants,
  Samsung first. The moment the TV responds you tap **IT WORKED**, give the
  venue a nickname, and the brand/variant is saved as a profile.
- **Manual Mode** — pick brand → variant and get a full remote pad: power,
  volume, channel, mute, input, arrows/OK, menu/exit/guide. Flip on
  **blast mode** to fire one button across *all* variants (rate-limited,
  cancellable) — the manual answer to "try this button everywhere".
- **Profiles** — saved TVs with venue nicknames; rename, set default, delete,
  and jump straight into Manual Mode with "Use".
- **Attempt Log** — every probe, transmit, and blast is recorded with variant,
  button, timestamp, and whether it worked. This is the attempt-analysis log.
- **Carrier diagnostics** — the app reads the phone's reported IR carrier
  ranges and warns when a variant's carrier (e.g. Philips 36kHz, Sony 40kHz)
  falls outside them, instead of failing silently. Unknown caps are fail-open
  (no warnings). Regression-tested by `tools/test_carrier.py`.

## IR database (audited, nothing invented)

`app/src/main/assets/ir_database.json` (11 variants, 146 buttons) is generated by
`tools/gen_ir_db.py` from real data:

- **Codes**: [probonopd/irdb](https://github.com/probonopd/irdb) —
  crowd-sourced protocol/device/subdevice/function tuples
  (per-variant source CSV URL is embedded in the JSON).
- **Timings**: [probonopd/MakeHex](https://github.com/probonopd/MakeHex) `.irp`
  protocol definitions, plus the Philips RC5 spec and Ken Shirriff's SIRC docs.

The generator self-verifies before writing anything (Samsung `E0E040BF`,
LG `20DF10EF`, a published Sony Bravia Pronto capture, a published RC5 Pronto
capture — 4/4 must pass or it aborts). `tools/test_db.py` re-validates the
shipped JSON: magic order (Samsung first), every variant has volume-up, sane
patterns, known-good spot checks. Variants whose timings are inferred rather
than sourced (currently only TCL / RCA-38) are flagged `verified: false` in the
JSON and shown with a warning in the app — confirm them on-device via Magic Mode.

Regenerate:

```bash
bash tools/fetch_irdb.sh        # re-fetch the irdb CSVs (GitHub, official source)
python3 tools/gen_ir_db.py      # verify + render -> app/src/main/assets/ir_database.json
python3 tools/test_db.py        # regression tests for the database
```

## Build

Requirements: Android Studio (Hedgehog or newer) with an Android SDK, or a
standalone Gradle + Android SDK install. Java 17.

```bash
cd remote
# first time only, if gradle/wrapper/gradle-wrapper.jar is absent:
gradle wrapper --gradle-version 8.7
./gradlew assembleDebug
# APK lands at app/build/outputs/apk/debug/app-debug.apk
```

Or just open the `remote/` folder in Android Studio and press Run.

Notes:
- `TRANSMIT_IR` is a normal install-time permission; the app also checks
  `hasIrEmitter()` and shows a notice on devices without an IR blaster.
- Dependencies are AndroidX/Kotlin only — no third-party SDKs.
- This is a pure-Compose app: `scripts/check-theme.sh` is a regression guard
  (no SDK needed) that fails if a view-based Material Components theme
  reference (`Theme.Material3.DayNight…`, `Theme.MaterialComponents…`,
  `com.google.android.material`) sneaks back into the XML or Gradle files.
  Run it before committing changes to themes or dependencies:
  `./scripts/check-theme.sh`
  (`androidx.compose.material3` Compose imports are legitimate and ignored.)

## Project layout

```
app/src/main/java/net/dogs/remote/
  MainActivity.kt          bottom-nav host (Magic / Manual / Profiles / Log)
  ir/IrDatabase.kt         audited JSON loader + validation
  ir/IrSender.kt           ConsumerIrManager wrapper
  ui/RemoteViewModel.kt    single source of truth; cancellable magic/blast jobs
  ui/MagicScreen.kt        one-tap variant sweep + IT WORKED flow
  ui/ManualScreen.kt       brand/variant picker + remote pad + blast mode
  ui/ProfilesScreen.kt     saved TVs: rename / default / delete / use
  ui/LogScreen.kt          attempt-analysis log
  data/ProfileStore.kt     SharedPreferences profile CRUD
  data/AttemptLog.kt       capped SharedPreferences attempt log
tools/
  gen_ir_db.py             auditable DB generator (4/4 self-verification)
  test_db.py               DB regression tests
  fetch_irdb.sh            re-fetch source CSVs from github.com/probonopd/irdb
  irdb_sources.md          observed function-name lists per source CSV
```

## On-device test checklist (OnePlus 12R)

1. Install debug APK, grant nothing (no runtime permissions needed).
2. Magic Mode → START MAGIC pointed at a Samsung TV → IT WORKED → nickname.
3. Profiles → Use → Manual pad drives the TV (power, vol, input…).
4. Manual → blast mode → one button sweeps all variants; Stop cancels.
5. Log shows every attempt; the worked one is marked WORKED.
6. Kill the app mid-sweep → no stuck emitter (jobs are scoped + cancellable).
